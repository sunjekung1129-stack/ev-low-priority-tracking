# EV Low Priority Tracking System (EV-LPTS) — กฟภ.

ระบบติดตามสถานะคำร้องขอใช้ไฟฟ้า EV Low Priority (สถานีอัดประจุไฟฟ้า แบบ Low Priority) ตั้งแต่รับคำร้องจนถึงบันทึกวันที่มีผลอัตรา Low

## เริ่มใช้งาน

ต้องใช้ Node.js 22.13 ขึ้นไป (ใช้ SQLite ที่มากับ Node ไม่ต้องติดตั้งฐานข้อมูลเพิ่ม)

```bash
npm install
npm start          # http://localhost:3000
```

บัญชีทดลอง (สร้างอัตโนมัติครั้งแรก): `field1` / `field2` (กฟส.ในพื้นที่ใช้ไฟฟ้า), `tfd1` (กทฟ.) รหัสผ่าน `pea1234` · `admin` / `admin1234`
**ก่อนใช้งานจริงให้เปลี่ยนรหัสผ่าน หรือปิดบัญชีทดลองในหน้า "ผู้ใช้งาน"**

ตัวแปรสภาพแวดล้อม: `PORT` (ค่าเริ่มต้น 3000), `DATA_DIR` (ที่เก็บฐานข้อมูลและไฟล์แนบ ค่าเริ่มต้น `./data`), `COOKIE_SECURE=1` (เมื่อใช้งานผ่าน HTTPS)

## นำเข้าข้อมูลจาก Excel

```bash
npm run import -- "C:\path\to\Book1.xlsx" --dry-run   # ตรวจสอบก่อน ไม่บันทึก
npm run import -- "C:\path\to\Book1.xlsx"             # นำเข้าจริง
```

- อ่านคอลัมน์จากชื่อหัวตาราง (แถวที่ 1) ตามรูปแบบไฟล์ Book1.xlsx เช่น `สถานี EV`, `กฟฟ.หน้างาน`, `Contract Acc. M/I`, `1.หนังสือ`, `4.หนังสือ`, `หนังสือเปลี่ยนอัตรา`
- แถวที่มี CA เดิมอยู่แล้วจะถูกข้าม จึงนำเข้าไฟล์ที่อัปเดตซ้ำได้โดยไม่เกิดรายการซ้ำ
- การจับคู่เงื่อนไข: ข้อ 1 = `Product list` (ขึ้นทะเบียนแล้ว), ข้อ 2 = `1.หนังสือ` + ผล `ตรวจสอบมาตรฐานการติดตั้งฯ`, ข้อ 3 = `4.หนังสือ` + ผล `ทดสอบปฏิบัติการโครงข่าย CPO - PEA EVMS`
- วันที่มีผลอัตรา Low ใช้ `วันที่หนังสือเปลี่ยนอัตรา` ส่วนผลทดสอบความปลอดภัย (`2.หนังสือ`, IEC 60364-6 / IEC 61851) แสดงในข้อ 9 ของข้อมูลคำร้อง

## ขั้นตอนการทำงาน

| ขั้น | ผู้ดำเนินการ | ในระบบ |
|---|---|---|
| 1. รับคำร้อง | กฟส.ในพื้นที่ใช้ไฟฟ้า | กรอกแบบฟอร์มขอใช้ไฟฟ้า EV Low Priority (ข้อ 1–9) + แนบ PDF แบบฟอร์มคำร้อง → ระบบแจ้งเตือน กทฟ. |
| 2. ชำระค่าทดสอบ | กฟส.ในพื้นที่ใช้ไฟฟ้า / กบล. กฟข. | บันทึกเลขที่คำร้อง (12 หลัก) ของค่าทดสอบความปลอดภัยและค่าทดสอบ CPO แล้วติ๊ก **"ลูกค้าชำระเงินแล้ว"** (หรือระบุ "ไม่ต้องชำระ" พร้อมเหตุผล) — ครบแล้วระบบแจ้ง กทฟ. และ กบล. กฟข. |
| 3. เงื่อนไขที่ 1 หลักฐานการขึ้นทะเบียนเครื่องอัดประจุไฟฟ้ากับ กฟภ. | กฟส.ในพื้นที่ใช้ไฟฟ้า / กบล. กฟข. | อัปโหลดไฟล์หรือลิงก์ (บันทึกได้หลังชำระครบ) |
| 4. เงื่อนไขที่ 2 ผลตรวจสอบมาตรฐานการติดตั้งก่อนติดตั้งมิเตอร์ | กฟส.ในพื้นที่ใช้ไฟฟ้า / กบล. กฟข. | อัปโหลดไฟล์หรือลิงก์ (บันทึกได้หลังชำระครบ) |
| 5. เงื่อนไขที่ 3 ผลการทดสอบระบบ CPO กับ PEA EVMS | กทฟ. | อัปโหลดไฟล์หรือลิงก์ (บันทึกได้หลังชำระครบ) · **สถานีที่ใช้ PEA VOLTA (ข้อ 8) ผ่านเงื่อนไขนี้อัตโนมัติ** ไม่ต้องทดสอบ และไม่แจ้ง กทฟ. — เทียบเคียงหลักเกณฑ์การทดสอบ CPO ตามหนังสือ กบท.(บย)683/2567 (อยู่ในเมนูเอกสารหลักฐานที่เกี่ยวข้อง หมวดเงื่อนไข) |
| 6. ชำระครบ + ครบ 3 เงื่อนไข | ระบบ | เปลี่ยนสถานะเป็น "รอเปลี่ยนอัตรา Low (SAP)" และแจ้งเตือน กฟส.ในพื้นที่ใช้ไฟฟ้า |
| 7. เปลี่ยนอัตราใน SAP | กฟส.ในพื้นที่ใช้ไฟฟ้า | ติ๊ก **"จัดทำข้อตกลงแก้ไขเพิ่มเติมสัญญาซื้อขายไฟฟ้าแล้ว"** (ต้องติ๊กก่อน ระบบจึงให้ใส่วันที่) แล้วบันทึกวันที่มีผลอัตรา Low Priority → **เสร็จสมบูรณ์ (เปลี่ยนอัตรา Low ในระบบ SAP แล้ว)** |

คำร้องที่นำเข้าจาก Excel ซึ่งระบุ "ไม่ต้องชำระค่าทดสอบ" จะถูกตั้งเป็น "ไม่ต้องชำระ" ทั้ง 2 รายการโดยอัตโนมัติ

หลักฐานแต่ละรายการเป็นได้ทั้ง **ไฟล์แนบ** หรือ **ลิงก์ (เช่น Google Drive)** พร้อมผล "ผ่าน/ไม่ผ่าน" และหมายเหตุ (ไม่มีช่องเลขที่/วันที่หนังสือ — เลขที่หนังสือที่นำเข้าจาก Excel เดิมยังแสดงตามเดิม)
เงื่อนไขถือว่าครบเมื่อมีหลักฐานอย่างน้อย 1 รายการที่ผล **ไม่ใช่ "ไม่ผ่าน"** เงื่อนไข 1–3 ทำพร้อมกันได้ ถ้าลบหลักฐานจนไม่ครบ สถานะจะกลับเป็น "รอเงื่อนไข" อัตโนมัติ

## หน้าจอหลัก

- **ภาพรวมและแผนที่** (หน้าแรก): เริ่มต้นแสดง**ทั่วประเทศ** (กฟส./กบล. สลับเป็น "พื้นที่ของฉัน" ได้) · 4 ช่องสรุปตามสถานะ (คำร้องทั้งหมด / รอเงื่อนไข / รอเปลี่ยนอัตรา Low / เสร็จสมบูรณ์) — ตัวเลขทั่วประเทศของ กฟส./กบล. ดูได้อย่างเดียว · ต่อด้วยแผนที่สถานี หมุดสีตามสถานะ หมุดของพื้นที่อื่นเป็นจุดเล็กสีจาง กดแล้วเห็นเพียงสถานะและ กฟส./จังหวัด (ไม่มีชื่อสถานีและเปิดคำร้องไม่ได้) กดที่สถานะเพื่อซ่อน/แสดง ค้นหาและกดรายชื่อเพื่อซูม (แผนที่ใช้ OpenStreetMap ต้องต่ออินเทอร์เน็ต)
- **รายการคำร้อง**: เฉพาะคำร้องของ กฟส. ตนเอง (กบล. = ทั้งเขต, กทฟ./ผู้ดูแลระบบ = ทุกพื้นที่) — ส่งออก CSV ก็ได้เฉพาะขอบเขตนี้ · 4 ช่องสรุปตามสถานะ (เหมือนหน้าภาพรวม) แถบความคืบหน้าทั้งหมด (กดคำอธิบายเพื่อกรองตามสถานะ) ตัวกรอง ค้นหา ส่งออก CSV · แต่ละแถวแสดงชื่อย่อ CPO ในกรอบสี่เหลี่ยม (PEA VOLTA = VOLTA, ข้อมูลเก่าที่นำเข้าจาก Excel ใช้ชื่อย่อบริษัท) ชื่อสถานีพร้อมหมายเลข CA, เงื่อนไข, สถานะ, วันที่ยื่น/วันที่มีผล Low และคอลัมน์ขวาสุดคือผลทดสอบความปลอดภัย (ไม่เป็นเงื่อนไข)
- **รับคำร้องใหม่**: ต้องกรอก CA, Meter No. และ**ต้องแนบ PDF แบบฟอร์มคำร้องขอใช้ไฟฟ้า** · **ข้อ 8 ระบบ CPO ต้องเลือกเสมอ**: PEA VOLTA หรืออื่นๆ (กรอกชื่อระบบ ชื่อย่อ CPO และผู้ให้บริการเอง) — ไม่มีช่องชื่อย่อบริษัท/แบรนด์แล้ว · กฟข. กำหนดอัตโนมัติจากรายชื่อ กฟส.
- **หน้าคำร้อง** มี 4 แท็บ: **ชำระเงินค่าทดสอบ** (บันทึกเลขที่คำร้อง 12 หลัก ห้ามซ้ำกับสถานีอื่น — ในสถานีเดียวกันค่าทดสอบความปลอดภัยกับค่าทดสอบ CPO ใช้เลขเดียวกันได้ — ของค่าทดสอบความปลอดภัย 10,000 บาท/เครื่อง และค่าทดสอบ CPO 2,400 หรือ 6,500 บาท/มิเตอร์ แล้วติ๊กชำระ) · **เงื่อนไข 3 ข้อ** (บันทึกได้หลังชำระครบ) · **ผลทดสอบความปลอดภัย** (ไม่ใช่เงื่อนไขในการเปลี่ยนอัตรา) · **ข้อมูลคำร้อง** — เปิดหน้าคำร้องที่ยังไม่ชำระจะเริ่มที่แท็บชำระเงิน
- **เอกสารหลักฐานที่เกี่ยวข้อง**: แบบฟอร์ม ข้อตกลง และระเบียบ แยกตามขั้นตอนงาน (รับคำร้อง · เงื่อนไข 1–3 · ทดสอบความปลอดภัย · เปลี่ยนอัตรา/สัญญา · ระเบียบ) ทุกบทบาทเปิดดู/ดาวน์โหลดได้ ผู้ดูแลระบบเพิ่ม/แก้ไข/ลบในหน้านั้น หรือใช้ `node scripts/add-document.js "<ไฟล์>" --title "..." --category conditions` · ไฟล์เก็บที่ `data/docs/` (ไม่อยู่ใน git และไม่ขึ้นเว็บเดโม)
- **การไฟฟ้า (กฟส.)** (ผู้ดูแลระบบ): รายชื่อ กฟส.ในพื้นที่ใช้ไฟฟ้า และ กฟข. ที่สังกัด (12 เขต: กฟน.1–3 กฟฉ.1–3 กฟก.1–3 กฟต.1–3) เพิ่มทีละแห่ง หรือ**วางรายชื่อจาก Excel** (2 คอลัมน์: ชื่อ กฟส., กฟข.) ได้ครั้งละหลายร้อยแห่ง

## ส่งข้อมูลไป Google Sheets / Google Drive

เมนู **เชื่อมต่อ Google** (ผู้ดูแลระบบ) — ติดตั้ง Apps Script ในชีทครั้งเดียว (ขั้นตอนและโค้ดพร้อมคัดลอกอยู่ในหน้านั้น)

- คำร้องทุกรายการ (ที่มีอยู่และที่เพิ่มใหม่) ถูกเขียนลงชีท 1 แถวต่อคำร้อง โดยใช้คอลัมน์ "เลขที่คำร้อง" เป็นคีย์ และอัปเดตทุกครั้งที่มีการเปลี่ยนแปลง — คอลัมน์ที่ผู้ใช้เพิ่มเองในชีทจะไม่ถูกแก้
- ไฟล์แนบทุกไฟล์ถูกอัปโหลดเข้า Google Drive ในโฟลเดอร์ของสถานี (ชื่อ `เลขที่คำร้อง ชื่อสถานี`) ลบไฟล์ในระบบ → ไฟล์ใน Drive ถูกย้ายไปถังขยะ
- ส่งผ่านคิวเบื้องหลัง ถ้าเน็ตหรือ Google ขัดข้องจะลองใหม่อัตโนมัติ ดูสถานะได้ในหน้าเดียวกัน
- โค้ด Apps Script อยู่ที่ `google-apps-script/Code.gs`, ฝั่งระบบอยู่ที่ `server/google-sync.js`

## สิทธิ์การใช้งาน

**กฟส. เห็นและบันทึกได้เฉพาะคำร้องของ กฟส. ตนเอง, กบล. เห็นและบันทึกได้ทุกคำร้องในเขตตนเอง** (ห้ามข้าม กฟส. ห้ามข้ามเขต) · กทฟ. และผู้ดูแลระบบเห็นทุกพื้นที่ · หน้าภาพรวมแสดง**ตัวเลขทั่วประเทศ**ให้ทุกบทบาท แต่เปิดดูคำร้องของพื้นที่อื่นไม่ได้ (เซิร์ฟเวอร์ปฏิเสธเสมอ ไม่ใช่แค่ซ่อนลิงก์)

- **กฟส.ในพื้นที่ใช้ไฟฟ้า**: คำร้องของ กฟส. ตนเอง — รับและแก้ไขคำร้อง แนบไฟล์คำร้อง อัปโหลดเงื่อนไข 1–2 (และแนบ PDF เงื่อนไขที่ 3 ได้เฉพาะตอนรับคำร้อง) ผลการตรวจวัดทดสอบความปลอดภัย บันทึกเลขที่คำร้องค่าทดสอบ บันทึกวันที่มีผลอัตรา Low และยกเลิกคำร้อง
- **กบล. กฟข.**: คำร้องใน กฟข. ตนเอง — บันทึกเลขที่คำร้องค่าทดสอบและการชำระเงิน อัปโหลดเงื่อนไข 1–2 บันทึกผลการตรวจวัดทดสอบความปลอดภัย และได้รับแจ้งเตือนเมื่อมีคำร้องใหม่ใน กฟข. ของตน
- **กทฟ.**: บันทึกเงื่อนไขที่ 3 ได้ทุกคำร้อง
- **ผู้ดูแลระบบ**: ทำได้ทุกอย่าง จัดการผู้ใช้และรายชื่อ กฟส.

เมื่อคำร้องเสร็จสมบูรณ์แล้ว จะแก้ไขข้อมูลหรือลบไฟล์ไม่ได้ (ผู้ดูแลระบบยังแก้ไขข้อมูลได้) ทุกการดำเนินการถูกบันทึกในแท็บ "ประวัติการดำเนินการ"

## โครงสร้าง

```
server/db.js      สคีมา SQLite, ผู้ใช้ทดลอง
server/index.js   REST API, สิทธิ์, workflow สถานะ, การแจ้งเตือน, อัปโหลดไฟล์
scripts/import-excel.js  นำเข้าข้อมูลจากไฟล์ Excel
public/           หน้าเว็บ (HTML/CSS/JS ไม่ต้อง build)
data/             ฐานข้อมูลและไฟล์แนบ (ไม่อยู่ใน git) — ควรสำรองข้อมูลโฟลเดอร์นี้
```

## สิ่งที่ควรเพิ่มก่อนใช้งานจริง

- เชื่อมการเข้าสู่ระบบกับ AD/SSO ของ กฟภ. แทนรหัสผ่านในระบบ
- แจ้งเตือนทาง Email/LINE เพิ่มเติม (ตอนนี้แจ้งเตือนในระบบอย่างเดียว ดูฟังก์ชัน `notify()` ใน `server/index.js`)
- จำกัดจำนวนครั้งการเข้าสู่ระบบผิด และใช้งานผ่าน HTTPS
